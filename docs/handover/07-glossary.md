# Glossary: RICS Payment Segment Tracker

## Terms

| Term | Meaning |
|---|---|
| As-of date | The date the member-year attributes load treats as today, which sets the current Campaign Year. By default it is the day the load runs. |
| Audit columns | The four columns every bronze table carries: _loaded_at (first landed), _updated_at (last changed by a load), _is_deleted (1 when no longer in the source) and _deleted_at (when it was marked as deleted). |
| Bronze | The layer of tables that copy source data one-to-one, with no change to any value, plus the audit columns. Their names start brnz_. |
| Campaign Year | The RICS subscription year, as held in Layercake.ref_campaign_year_config and on the invoice source. |
| Carried forward | A segment value copied from the latest earlier Campaign Year with an eligible invoice, because the year itself has none. Marked by a carried flag of 1 (payment_method_carried, payer_type_carried, concession_type_carried). Concessions are carried only when perpetual (assumed, Q-006). |
| Concession reference | The source list of concession types. Assumed to be CE.vwConcessionType, awaiting Q-008; landed in Layercake.brnz_concession. |
| Concession type | A reduced or nil subscription rate a member can hold, such as Retired or Exceptional Hardship, as listed in the concession reference. |
| Concession type list | Layercake.silv_ref_concession_type: the three reserved values, one 'No concession' row and one row per source concession type, each with an id that never changes, its invoice item code and its full-concession and perpetual flags. Copied to the concession type dimension, Layercake.dim_concession_type. |
| corporate_account_ref | On the member-year attributes, the scheme number of the contact's live corporate subscription in a Corporate year; empty in every other year (assumed, Q-019). |
| Corporate subscription | A contact's place in a corporate scheme subscription for a Campaign Year, as held in Subs.vwCorpSubscriptions and landed in Layercake.brnz_corporate_subscription. |
| Corporate status profile | Layercake.usp_profile_corp_subscription_status: counts rows of Subs.vwCorpSubscriptions by each 'Sub Status' and 'Sub User Status' value (Q-027). |
| Count-only query | A read-only query that returns counts, sums or rates only, never individual records, so it can be run on real data safely. |
| Credit note | A document on the invoice source whose number contains 'FTCN', or contains 'CRE' unless its full amount is exactly 0 (RULE-014). A credit note is never an eligible invoice. |
| Currency list | Layercake.silv_ref_currency: one row per currency code found on the subscription invoices, each with an id that never changes. Copied to the currency dimension, Layercake.dim_currency. |
| Current Campaign Year | The Campaign Year in Layercake.ref_campaign_year_config whose start and end dates cover the as-of date. The member-year attributes run up to and including it. |
| Dimension | A gold table that reporting uses to show a segment by name, such as Layercake.dim_payment_method, Layercake.dim_payer_type, Layercake.dim_currency or Layercake.dim_concession_type. Their names start dim_. |
| Double payment | A segment invoice settled both by Corporate and by another payment method. The contact-year is Corporate where a live corporate subscription exists, otherwise Individual (RULE-026, assumed, Q-002). |
| Eligible invoice | A subscription invoice that may set a contact-year's segments (RULE-014): not a credit note, not fully credited and not fee-only. A fully credited invoice is eligible only when the contact-year has no other eligible invoice (assumed, Q-012). Listed by Layercake.vw_silv_eligible_invoice. |
| Event tables | The Phase 1 tables Layercake.silv_membership_events (silver) and Layercake.fact_membership_events (gold), one row per membership event (Join, Change, Lapse, Readmission, Renewal). |
| Fee-only invoice | An invoice whose own lines include at least one enrolment or application fee line and are otherwise only tax. It is not an eligible invoice. |
| Full concession | A concession type whose discount in the concession reference is exactly 100; any other discount is a reduced concession (RULE-047). Marked by is_full_concession. |
| Fully credited | An invoice whose fully-credited value is 'Y'; 'N', 'N/A' and a missing value are not fully credited. |
| Gold | The layer that reporting reads: the dimensions and the fact tables. |
| Grain | What one row of a table represents, for example one invoice line or one whole transaction. |
| Grain profile | Layercake.usp_profile_custtrans_grain: counts invoices in synapse_fo.CUSTTRANS_RICS by rows, different item codes and tax rows, to show the source's grain (Q-021). |
| Item code (productcode) | The code on an invoice row that says what the row is for, for example a subscription, a fee or a concession. The line-type mapping turns it into a line type, and each concession type carries the item code its invoice lines use. |
| Last settlement voucher | On a credit or payment row in synapse_fo.CUSTTRANS_RICS, the voucher of the invoice it settles (RULE-077). |
| Layercake | The database schema that holds the Phase 1 membership solution and every object this solution adds. |
| Line type | What an invoice line is for: subscription, concession, readmission fee, enrolment or application fee, tax, other, or unmapped (RULE-028). |
| Line-type mapping | Layercake.silv_ref_invoice_line_type: the table that gives the line type of each item code and RIC invoice type pair. New codes are added as 'unmapped'; a person sets their line type by hand, and the load never overwrites it. |
| Live corporate subscription | A row in Subs.vwCorpSubscriptions for the contact and Campaign Year where both 'Sub Status' and 'Sub User Status' are active. Which value means active is an assumption ('Active') awaiting Q-027. |
| Live row | A bronze row whose source row still exists (_is_deleted 0). |
| Load log | Layercake.etl_run_log: one row per load run, with its outcome ('Success' or 'Failed') and the rows inserted, updated and deleted. |
| load_id | On a dimension, reference list or member-year attributes row, the load log entry of the load run that last wrote the row. |
| Marked as deleted (soft delete) | A bronze row whose source row has gone is kept, with _is_deleted set to 1 and _deleted_at recorded, rather than removed. |
| Member-year attributes | Layercake.silv_member_year_attributes: one row per contact per Campaign Year, from the contact's first membership event to the current Campaign Year, holding the year's payment method, payer type, corporate_account_ref and concession, each segment with a carried flag. |
| Migration | A numbered, recorded change to the database (MIG-nnnn), with an up script that applies it and a down script that reverses it. |
| No concession | The row of the concession type list for a member whose invoice carries no concession. It is put in place by the migration, not read from the source. |
| Paid position | In Phase 1, a contact's paid invoice position for a Campaign Year (Full Concession, Fully Paid, Partially Paid or Pre-Subs Payment), held in Layercake.silv_payment_events. Needed for a contact-year to be Individual. |
| Payer type | The segment that marks each membership event and paid member as Individual or Corporate. Its list of values is Layercake.silv_ref_payer_type. |
| Payment line | A live row of the invoice lines, on the invoice's own account, whose last settlement voucher is the invoice's voucher and which carries a payment mode. Payment lines decide the payment method when the segment invoice has no payment mode (RULE-013). |
| Payment method | One of the five ways a member pays that the dashboard filters on: Direct Debit, Card, Bank transfer, Cheque and Corporate. There is no Mixed method, an assumption awaiting Q-015. |
| Payment mode code | The code the finance system records for how an invoice or payment is paid: DD, Card, Bank, Cheque or Corporate. Layercake.fn_map_payment_method turns it into a payment method. |
| Perpetual concession | A concession type marked Perpetual (value 200000000) in the concession reference; every other value, including Non-Perpetual and a missing value, is not perpetual (RULE-094). Marked by is_perpetual. |
| Phase 1 | The existing Layercake membership solution that this solution extends without changing its results. |
| Reference list | A silver table listing the values of a segment or code, with ids or keys that never change, for example Layercake.silv_ref_payment_method, Layercake.silv_ref_payer_type, Layercake.silv_ref_currency or Layercake.silv_ref_concession_type. Their names start silv_ref_. |
| Reserved values | Three fixed entries in every segment list: 0 Unknown (the source has no value), -1 Unrecognised (the source has a value the mapping does not know) and -2 Not applicable (no value is expected). |
| RIC invoice type (ricinvoicetype) | The invoice type recorded on each row of synapse_fo.CUSTTRANS_RICS. With the item code, it identifies a row of the line-type mapping; a missing type is treated as empty. |
| Round | A column in Subs.vwCorpSubscriptions marking a tranche of processing of corporate records; later rounds may change it. It is not landed and plays no part in the solution. |
| Scheme No (scheme number) | The number of a corporate scheme subscription in Subs.vwCorpSubscriptions. With the contact number and Sub Campaign Year, it identifies a corporate subscription row. |
| Segment invoice | The eligible invoice that sets a contact-year's payment method, payer type and concession: the latest by transaction date (RULE-079, assumed, Q-012), ties to the higher row key (Q-036). |
| Sub Status, Sub User Status | In Subs.vwCorpSubscriptions, the status of the corporate subscription and the status of the subscription user. |
| REQ, RULE, AC, Q | Specification identifiers: a requirement, a business rule, an acceptance criterion and an open question to the client. |
| MOD, TC, ADR | A module of the build, a test condition, and an architecture decision record. |
| Silver | The layer of tables between bronze and gold: reference lists, attributes and matches. |
| Synthetic data | Made-up test data, used for all automated testing; no real data is used in testing. |
| Unmapped | The line type given to an item code that has not yet been mapped. Amounts on unmapped lines are left out of the subscription and fee amounts, and the event is flagged 'Unmapped lines' (RULE-030). |
| Voucher | The reference that links an invoice in Subs.tblSubsInvoices to its rows in synapse_fo.CUSTTRANS_RICS: an invoice's own lines carry its voucher (RULE-077). |
