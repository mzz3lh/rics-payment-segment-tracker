## Permission levels

| Level | Meaning |
|---|---|
| `none` | No access. |
| `metadata_read` | See object definitions (schemas, columns, procedures). Cannot read rows. |
| `data_read` | Metadata plus SELECT on all tables and views. |
| `test_execute` | Data read plus run tSQLt tests (tSQLt needs to fake tables and create test schemas). |
| `build` | Create and change objects, read and write data, run tests. Database-scoped only. |

## Rules

- No agent can grant access. Roles hold no GRANT, ALTER ANY USER, db_owner or server-level rights.
- No agent has any access to environments where `agents_allowed` is false (production).
- A human reviews and runs the generated SQL in `src/sql/setup/`. Agents never run it.
- Every agent connects with its own login, so the step log and SQL audit identify the actor.
